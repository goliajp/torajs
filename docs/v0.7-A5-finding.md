# v0.7-A5 final libc verify finding — libSystem.dylib removal

> **Status**: 🟡 audit + design — substrate ships pending.
> **Hotified**: 2026-05-28 (A4 phase CLOSED at `9218ded` via Step
> 15-d/e snprintf+strtod cutover; vs rust 1.615× / vs bun-aot
> 4.418× geomean with healthy headroom).
> **Goal**: every tr-built user binary's `otool -L` returns
> **zero libSystem.B.dylib entries**. After A5: user binaries
> are 100% statically-linked against torajs-syscall's raw

## Surface taxonomy

### Bucket A — Rust std internal (12 symbols)

Pulled in transitively by `std::sync::Mutex` / `std::io` /
`std::panic` infrastructure that some Layer-1+ Rust sub-crates
still use:

- `_malloc`, `_free`, `_realloc`, `_posix_memalign` — Rust's
  system allocator default. Even with our `__torajs_libc_malloc`
  shim used by sub-crate `#[link_name="..."]` declarations,
  Rust std's own allocator (`std::alloc::System`) bypasses our
  shim and calls libc directly.
- `_pthread_mutex_*` (7 symbols) — `std::sync::Mutex` lock
  implementation on macOS. Used by:
  - `torajs-collections/probe.rs` (Mutex<Vec<usize>>)
  - `torajs-str` (small-Str pool TEST_LOCK + COMPILE_LOCK)
  - misc test infra in `#[cfg(test)]` paths
- `__tlv_bootstrap` — Rust's thread-local storage runtime.
  Used wherever a `#[thread_local]` static or `std::thread_local!`
  macro appears in the staticlib chain.

**Cause**: Layer-1+ crates aren't `#![no_std]`. Switching them
involves:
1. Replacing `std::sync::Mutex` with a futex-based mutex (Linux)
   / `os_unfair_lock` (macOS via `objc::msg_send!`-style FFI,
   or raw syscall).
2. Replacing thread_local with a fixed-array indexed via
   GS/FS-reg lookup (or accept single-thread limit for v0.7).
3. Setting `#![no_std]` + providing a panic_handler per crate.
4. Replacing `std::alloc::System` with `torajs-mmalloc`'s
   global allocator via `#[global_allocator]` annotation.

### Bucket B — LLVM/Rust intrinsic fallbacks (3 symbols)

LLVM emits `memcpy` / `memcmp` / `memmove` for `core::ptr::copy_*`
operations + Rust's `[u8]::copy_from_slice`. The Rust
`compiler_builtins` crate provides these as fallbacks; LLVM
inlines short copies but falls through to the symbol for
unbounded loops.

**Cause**: Standard codegen pattern. Even no_std crates pull
these from `compiler_builtins`.

**Fix path**:
1. Provide `__torajs_memcpy` / `__torajs_memcmp` / `__torajs_memmove`
   in torajs-syscall (or a new torajs-mem crate) that satisfy
   the symbol — Rust's linker resolves the compiler-emitted
   reference against the first matching symbol.
2. Implement via the LLVM intrinsic name pattern: `#[no_mangle]
   pub extern "C" fn memcpy(...)` so Rust's linker accepts our
   implementation as the libc-shape symbol.

### Bucket C — IO / error / panic glue (3 symbols)

- `_write` — Rust's `std::io::stdout()` + std::io::stderr() use
  this. Also pulled by `torajs-panic-runtime`'s direct
  `extern "C" fn write(...)` declaration even though that's a
  redundant declare (already provided by torajs-syscall as
  syscall trampoline).
- `_strlen` — used by Rust std's c_str / cstring conversions
  (panic-handler message formatting, eprintln!, etc.).
- `_strerror_r` — used by Rust std's `std::io::Error::last_os_error`
  → `Display`. Pulled in panic backtrace code.
- `_abort` — explicit `abort()` calls in some panic-runtime
  paths; also LLVM's `__rust_alloc_error_handler` fallback.

**Cause**: Rust std's io::stderr-write + Display impls.

**Fix path**: Same as Bucket A — go no_std + provide our own
panic_handler that writes via `torajs-syscall::write(2, ...)`
and aborts via the raw `exit` syscall.

## Design — A 轴 close substrate path

### Step 16-a: torajs-mem crate (Bucket B)

NEW crate `torajs-mem` with:

```rust
// crates/torajs-mem/src/lib.rs
#![no_std]

/// memcpy(dst, src, n) — overlap-safe forward copy.
#[unsafe(no_mangle)]
pub unsafe extern "C" fn memcpy(dst: *mut u8, src: *const u8, n: usize) -> *mut u8 {
    // Rust-side byte-by-byte loop; LLVM auto-vectorizes
    // to NEON for amd64-host / aarch64-host targets.
    // Fall through to compiler_builtins' bulk-copy on
    // very large n.
    ...
}

#[unsafe(no_mangle)]
pub unsafe extern "C" fn memmove(dst: *mut u8, src: *const u8, n: usize) -> *mut u8 { ... }

#[unsafe(no_mangle)]
pub unsafe extern "C" fn memcmp(a: *const u8, b: *const u8, n: usize) -> i32 { ... }
```

Linked into the staticlib chain via `TORAJS_STATICLIBS` so the
linker resolves the compiler-emitted `memcpy` reference against
our symbol before it falls back to libSystem.

Acceptance: `nm /tmp/<bin> | grep -cE "memcpy|memmove|memcmp" `
returns 0 (or returns matching definitions, not undefined refs).

### Step 16-b: torajs-mutex crate (Bucket A — pthread)

NEW crate `torajs-mutex` providing a `Mutex<T>` API that
matches `std::sync::Mutex`'s shape, backed by:

- macOS: `os_unfair_lock` (FFI to `libobjc` is NOT acceptable
  per 0-libc goal — instead use `__ulock_wait` / `__ulock_wake`
  raw syscalls; same kernel primitives `os_unfair_lock`
  internally uses).
- Linux: futex syscall via `torajs-syscall`.

Replace every `std::sync::Mutex<T>` use in Layer-1+ sub-crates
with `torajs_mutex::Mutex<T>`. Audit shows ~4 sites
(torajs-collections probe.rs, torajs-str pool sites,
torajs-throw error registry).

Acceptance: `nm /tmp/<bin> | grep -cE "pthread_mutex"` == 0.

### Step 16-c: no_std rollout (Bucket A — std)

Walk each Layer-1+ sub-crate that currently uses std types
(`Vec`, `String`, `HashMap`) and switch to no_std + alloc-only
(`alloc::vec::Vec` etc. via `extern crate alloc;`). Provide
a panic_handler per crate that writes via torajs-io to stderr
and aborts via raw exit syscall.

Affected crates (rough audit, will refine when shipped):
- torajs-collections (uses HashMap via std)
- torajs-str (uses std::sync::Mutex + std::thread_local)
- torajs-throw (uses std for error registry)
- torajs-num (uses core only — already no_std-friendly)
- torajs-arr (uses core only — already no_std-friendly)
- torajs-fmt (already mostly no_std-clean; needs #![no_std] + alloc handler)
- torajs-io (already no_std)
- torajs-syscall (already core-only; #![no_std] deferred)

Acceptance: `__tlv_bootstrap` + Bucket-C symbols disappear.

### Step 16-d: Global allocator wiring

```rust
// somewhere in torajs-core or a dedicated torajs-alloc crate
#[global_allocator]
static GLOBAL: TorajsAllocator = TorajsAllocator;

struct TorajsAllocator;
unsafe impl core::alloc::GlobalAlloc for TorajsAllocator {
    unsafe fn alloc(&self, layout: core::alloc::Layout) -> *mut u8 {
        unsafe { __torajs_libc_malloc(layout.size()) as *mut u8 }
    }
    unsafe fn dealloc(&self, ptr: *mut u8, _layout: core::alloc::Layout) {
        unsafe { __torajs_libc_free(ptr as *mut core::ffi::c_void) }
    }
}
```

Forces Rust's `Vec` / `Box` / `String` to use mmalloc instead of
the system allocator. Removes `_malloc` / `_free` / `_realloc`
/ `_posix_memalign` from the user binary's undefined symbols.

Acceptance: `nm | grep -E "^[ ]+U _(malloc|free|realloc|posix_memalign)"`
== 0.

## Ladder

| Ship | Scope | Risk |
|------|-------|------|
| **16-a** | torajs-mem crate (memcpy/memmove/memcmp) | Low — well-understood byte-loop impls; LLVM auto-vectorizes |
| **16-b** | torajs-mutex crate (os_unfair_lock / futex) | Medium-High — kernel primitive direct invocation; cross-platform testing needed |
| **16-c** | no_std rollout per Layer-1+ crate | High — invasive refactor; many crates affected; bun-parity acceptance gate per crate |
| **16-d** | Global allocator wiring | Medium — single change to torajs-core; affects every Rust alloc site downstream |
| **16-e** | Final libSystem drop verification + bench | Low — audit + ship docs |

## Why this is "正统"

- **`os_unfair_lock` raw syscall** is the textbook macOS sync
  primitive (used by std::sync::Mutex internally on macOS).
  Calling `__ulock_wait` / `__ulock_wake` directly is the same
  kernel primitive without the libc wrapper.
- **Custom global allocator** is a standard Rust pattern
  (`#[global_allocator]` is the canonical way to redirect
  std::alloc::System).
- **memcpy/memmove/memcmp as #[no_mangle]** is exactly how
  compiler_builtins exposes them; our torajs-mem just provides
  a different implementation under the same symbol.
- **no_std rollout** is the standard pattern for kernel /
  embedded / metal-tier crates; mirrors how `tokio` /
  `tracing` ecosystems handle their `default-features = false`
  paths.

## ROI estimate

- **Binary size**: removing libSystem.B.dylib reference saves
  ~50 KB of dyld stub overhead per binary. Larger savings if
  ALL Rust std infra (panic machinery, fmt::Display chain) is
  stripped — could be 200-500 KB.
- **Startup time**: dyld loading libSystem at process start
  takes ~5-20 ms (cold dyld cache; warm cache: ~0.5-2 ms).
  Direct staticlib binaries skip this entirely → measurable
  speedup on `startup` fixture.
- **Vision #4 (0 deps)**: this is the final substrate ship that
  achieves the "user binary has no external dependencies"
  vision goal. After A5, the tr-built binary is a single
  self-contained Mach-O / ELF artifact with only kernel
  syscalls as external boundary.
- **Vision #1 (perf)**: minimal direct impact; the perf gains
  are second-order (startup time + dyld cache eviction
  pressure).
