## Why now

Step 5d (AnyBox struct shrink 24 → 16 B) shipped + reverted (`ca96c02` →
`cd7c05e`, 2026-05-26). Conformance dropped to 614 / 71 / 1 because
**ssa_lower has 10+ direct `Load i64 @+8 (tag) / @+16 (value)` IR-emit
sites** that bypass the FFI shims migrated in Step 5c. Same failure class
as Step 4c arr revert: Rust-side migration was safe, but **layout change
demands IR-emit co-migration**.

Step 5d-v2 (port the 10+ IR-emit sites to read tag from header bits 8..11
+ value from new offset 8) is the obvious fix, but it is **transitional
work that Step 7 throws away**: NaN-box eliminates the AnyBox struct
entirely and every one of those 10+ sites gets rewritten as an immediate
`u64` decode. Doing Step 5d-v2 + Step 7 in sequence = the same IR-emit
sites touched twice. **Ceiling-first** (per the project HARD RULE):
collapse the two into one architectural change.

This doc fixes the Step 7 design before any commit lands.

## Goal (terms)

Replace the heap-allocated 24-byte `AnyBox { header, tag: i64, value: i64 }`
with a 64-bit immediate value type that encodes every JS value:

- `null`, `undefined`, `true`, `false` — immediate constants
- 32-bit signed integers — inline payload (full Int32 range)
- IEEE 754 doubles — transparently as `f64` bits
- Heap pointers (Str / Arr / Obj / Closure / RegExp / Date / Promise /
  Symbol / BigInt / WeakRef / WeakMap / WeakSet / DynObj / Map / MapIter
  / ArrIter) — 48-bit user-VA payload

8 bytes per Any (was 24 B). Array<Any> slot stride 16 → 8 B. Object slots
holding Any 16 → 8 B. dynobj bucket value 16 → 8 B (key tag/value pair
shrinks accordingly).

No allocation for primitive Any values (Int32 / f64 / Bool / Null / Undef).
Only Heap values allocate, and there the AnyBox is **gone** — the Any
slot directly stores the underlying heap pointer.

## Layout — JSC-style "double-encode offset"

The canonical mainstream design (used in JavaScriptCore for ~15 years, well-
documented, tested at billion-page scale). Picking the proven path over
inventing a torajs-specific variant satisfies the **正统 / mainstream**
pillar of the design principles.

### Bit assignment

```text
typedef u64 AnyValue;

// Top-16-bit tag region (after a DoubleEncodeOffset additive trick keeps
// real f64 doubles in a contiguous range NOT colliding with these tags).
const u64 TagTypeNumber       = 0xFFFE_0000_0000_0000;  // Int32 sentinel
const u64 DoubleEncodeOffset  = 0x0007_0000_0000_0000;  // 2^50 + 2^49 + 2^48
const u64 TagBitTypeOther     = 0x0000_0000_0000_0002;  // null/undef/bool
const u64 TagBitBool          = 0x0000_0000_0000_0004;
const u64 TagBitUndefined     = 0x0000_0000_0000_0008;

const AnyValue ValueFalse     = TagBitTypeOther | TagBitBool | 0;   // 0x06
const AnyValue ValueTrue      = TagBitTypeOther | TagBitBool | 1;   // 0x07
const AnyValue ValueNull      = TagBitTypeOther;                    // 0x02
const AnyValue ValueUndefined = TagBitTypeOther | TagBitUndefined;  // 0x0A
```

### Decoding rules (single-conditional fast paths)

```text
v: AnyValue (u64)

// is_int32 — top 16 bits == 0xFFFE
fn is_int32(v) -> bool:
  (v & 0xFFFF_0000_0000_0000) == 0xFFFE_0000_0000_0000

// extract_int32 (assumes is_int32)
fn as_int32(v) -> i32:
  v as i32      // low 32 bits, sign-extended

// is_double — top 16 bits >= 0x0001 AND != 0xFFFE
// equivalent: v & TagTypeNumber != 0 AND not is_int32
// classic JSC test: (v & TagTypeNumber) != 0 implies not-pointer
//   then subtract DoubleEncodeOffset bit-pattern to recover f64
fn is_double(v) -> bool:
  (v & TagTypeNumber) != 0 && !is_int32(v)

// extract_double (assumes is_double)
fn as_double(v) -> f64:
  f64::from_bits(v - DoubleEncodeOffset)

// is_cell (heap pointer)
fn is_cell(v) -> bool:
  (v & TagTypeNumber) == 0 && v != 0  // top 16 bits all zero

// extract_pointer (assumes is_cell)
fn as_pointer(v) -> *mut HeapHeader:
  v as *mut HeapHeader     // 48-bit aarch64 user-VA fits directly

// is_null / is_undefined / is_bool / is_true / is_false
fn is_null(v) -> bool:       v == ValueNull
fn is_undefined(v) -> bool:  v == ValueUndefined
fn is_bool(v) -> bool:       (v & ~1) == ValueFalse
fn as_bool(v) -> bool:       (v & 1) != 0
```

### Encoding rules

```text
fn box_int32(x: i32) -> AnyValue:
  TagTypeNumber | (x as u32 as u64)

fn box_double(x: f64) -> AnyValue:
  f64::to_bits(x) + DoubleEncodeOffset

fn box_pointer(p: *mut HeapHeader) -> AnyValue:
  p as u64       // aarch64 user-VA, top 16 bits already 0

fn box_bool(b: bool) -> AnyValue:
  if b { ValueTrue } else { ValueFalse }
```

### Why this layout (vs the alternatives I considered)

| Alternative | Why rejected |
|---|---|
| sNaN-payload tag (3-bit tag in mantissa bits 48–50) | Tag extract = `lshr 48; and 0xF; cmp` (3 IR ops); JSC offset gives `cmp top16 == const` (1 IR op + and). |
| V8-style 32-bit tagged ptrs | aarch64 user pointers are 48-bit; 32-bit ptr-compression needs a per-process heap base which adds an indirection on every deref. |
| Mozilla "pointer-as-NaN" | More complex int/bool encoding; same decode latency on Int32 fast path. |

The JSC offset trick keeps the f64 decode at `sub` + `bitcast`, the most
common operation. Int32 + Bool / Null / Undef + Cell are all 1-cmp fast
paths.

## ABI impact

The ABI **changes** — every callsite that currently exchanges
`(tag: i64, value: i64)` pairs with the runtime collapses to a single
`AnyValue: i64`. Specifically:

- `__torajs_any_box(tag, value)` → **deleted** (no allocation needed)
- `__torajs_any_unbox_tag(box)`, `__torajs_any_unbox_value(box)`,
  `__torajs_any_box_drop(box)` → **deleted** (Any values are immediate;
  drop is a tag-test + rc_dec if `is_cell`)
- `__torajs_any_payload_rc_inc(tag, value)` → **rewritten** to
  `__torajs_any_rc_inc(v: AnyValue)`; tag-test inside
- `__torajs_any_compare(op, lt, lv, rt, rv)` → `(op, l: AnyValue, r: AnyValue)`
- `__torajs_any_arith(op, lt, lv, rt, rv) -> *AnyBox` →
  `(op, l: AnyValue, r: AnyValue) -> AnyValue`
- `__torajs_any_add(lt, lv, rt, rv) -> *AnyBox` → `(l, r) -> AnyValue`
- `__torajs_any_to_str(tag, value) -> *Str` → `(v: AnyValue) -> *Str`
- `__torajs_any_to_number(box_ptr) -> f64` → `(v: AnyValue) -> f64`
- `__torajs_any_strict_eq(box_ptr, rhs_tag, rhs_value)` → `(l, r: AnyValue)`
- `__torajs_any_typeof`, `__torajs_print_any`, `__torajs_any_to_bool` →
  args become `AnyValue` instead of `*const AnyBox`

`torajs-meta/reflect.rs::__torajs_get_proto_of_any` /
`__torajs_get_property_descriptor` take `AnyValue` arguments; the
dynobj-set bucket-value pair `(tag, value)` collapses to a single
`AnyValue`, so `__torajs_dynobj_set/has/get_tag/get_value/get_flags`
shrink to `(dynobj, key, v: AnyValue) / (dynobj, key) -> AnyValue` (the
tag is encoded in the value).

ssa_lower IR-emit: every Any-typed slot read becomes a single `i64 load`
(was `i64 load @+8` for tag + `i64 load @+16` for value, then a call into
`__torajs_any_box` to wrap into a heap pointer). Every Any-typed write
becomes a single `i64 store`. Tag-discriminated dispatch (10+ sites in
`ssa_lower.rs`) rewrites against `AnyValue` decode primitives instead of
loading raw offsets.

## Substrate touchpoints

Crates / files that hold an AnyBox-shaped concept and need to migrate:

| Crate | Touchpoint | Migration |
|---|---|---|
| `torajs-anyvalue` | `AnyBox` struct + 13 FFI shims | **Deleted**; replaced by `AnyValue = u64` const fns + new FFI shims. Module reorganises into `nanbox/{layout,decode,encode,arith,compare,coerce,ffi}.rs`. |
| `torajs-rc` | `ANY_TAG_*` constants + `HeapHeader::any_tag_bits/set_any_tag` (Step 5a) | **Deleted** (no longer needed — tag lives in the AnyValue word itself, not the heap header). |
| `torajs-meta::reflect` | `ANY_BOX_TAG_OFF / VAL_OFF` direct reads | Replaced by AnyValue decode helpers. |
| `torajs-dynobj` | Bucket layout `{ key_ptr, tag, value }` (24 B) | Bucket `{ key_ptr, AnyValue }` (16 B). |
| `torajs-arr` (Array<Any> path) | Slot `{ tag, value }` (16 B) | Slot `AnyValue` (8 B). |
| `torajs-collections::Map` (Map<K, V> when V = Any) | Bucket value pair | Single AnyValue. |
| `torajs-core::ssa_lower` | 10+ direct offset loads + every Any-callsite | Rewritten against AnyValue decode/encode. **Biggest commit.** |
| `torajs-core::ssa_inkwell` | extern declares for the deleted shims | Updated to the new shim signatures. |
| `torajs-runtime::runtime_str.c` glue | `__torajs_any_to_str` + `__torajs_value_drop_heap` | `any_to_str` becomes `(AnyValue) -> *Str`; `value_drop_heap` is now called by `__torajs_any_rc_dec` on `is_cell` values only. |

The 10+ ssa_lower direct-offset sites are exactly the ones Step 5d-v2
would have touched — Step 7 touches them once, in the right way.

## Risks (acknowledged, not blocking)

1. **f64 NaN aliasing**: A user JS program that bit-fiddles a NaN via
   `Float64Array` could observe a NaN whose bits match a tagged-value
   sentinel. Mitigation: canonicalize NaN on `Float64Array` writes (one
   bitwise op on the store path). Decision deferred to 7d when the
   numeric path is touched.
2. **Pointer top-16-bit assumption**: We rely on aarch64 user-VA being
   ≤ 48 bits. Verified true on darwin/aarch64 (the only target until
   v0.7-C lands the self-hosted codegen). Linux/aarch64 + Linux/x86_64
   = same assumption holds.
3. **Bench surprises**: NaN-box decode is `cmp + sub + bitcast` on the
   double fast path — branchless on aarch64. Inkwell IR should lower to
   2–3 instructions. Worst case: hot loops with mixed-type Any operands
   see slightly more code per iteration. Mitigation: measured at 7g, no
   pre-commitment.
4. **Migration breakage during 7c–7e**: ssa_lower is 28800 LOC of which
   ~10% reads AnyBox layout in any way. Per-commit conformance gate is
   the safety net; a fail = revert + audit, same protocol as Step 4c /
   Step 5d.

## Decision points needing takagi sign-off

1. **Pick this JSC offset layout vs sNaN-payload tag** — recommendation
   is JSC (one-cmp fast paths, mainstream pedigree).
2. **NaN canonicalization on Float64Array writes** — necessary for the
   layout but adds 1 cycle per store. Decision: ship it. (Open: is the
   conformance gate sensitive enough to catch a missing canonicalization?
   probably yes via any `Float64Array` test, which we have.)
3. **Deletion of `torajs-rc::any_tag` (Step 5a output)** — yes, no longer
   needed; revert as part of 7b.
4. **Step 5b/5c effective overhead** — Step 6 bench (in flight) measures
   it. If perf-positive: keep until 7b deletion. If perf-negative: revert
   5b+5c before 7b for a clean slate.

## What 7a is NOT

This doc fixes the **layout** and the **migration shape**. It does not
fix:
- Exact LLVM IR sequences for each decode (ssa_inkwell side).
- The garbage-handling on `Float64Array` aliasing (decision: ship a
  canonicalization step; precise impl deferred to 7d).
- Bench numbers (deferred to 7g — see acceptance gate).

These are 7b–7g implementation territory; pinning them now would lock
in details before measurement.
