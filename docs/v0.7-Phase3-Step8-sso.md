## Why now

Step 7 collapsed the 24-byte boxed `AnyBox` into a 64-bit immediate. For
primitives (Int32 / f64 / Bool / Null / Undef) this means **zero heap
allocation per Any**. For heap values (Str / Arr / Obj / ...) the
immediate stores a 48-bit pointer — still one alloc per heap object.

For **short strings** (1–5 byte ASCII: `"1"`, `"42"`, `"true"`, `"null"`,
`":"`, `"["`, JSON tokens, single-char concat results, `charAt` returns,
small `Number.toString` results, etc.) the heap alloc + 8-byte header +
8-byte len + N-byte payload + per-use rc_inc/rc_dec **dominates the
per-call cost** versus what the bytes themselves carry.

SSO inlines those bytes directly into the 64-bit AnyValue payload — the
NaN-box already has unused bit space; ShortStr claims it. Mainstream
prior art: V8 (`ConsString` not SSO, but external one-byte strings have
similar inlining for ≤7 byte payloads); JavaScriptCore (`JSString` 7-byte
inline path); Rust `compact_str` / Swift small-string. Picking the
proven small-string-in-tagged-value path satisfies **正统 / mainstream**.

### Where the win lands (and where it does NOT)

**Wins** — runtime-computed short strings:

- `Number.toString()` for 0..99 999 (1–5 bytes covers 0..9999 plus most
  common 5-digit results)
- `String.fromCharCode(c)` / `charAt(i)` / `charCodeAt(i).toString()` for
  1–2 byte results
- `JSON.parse` token Strs (`"{`, `}`, `[`, `]`, `:`, `,`, single-char keys)
- `Array.prototype.join(sep)` short separators
- `String.prototype.slice(s, e)` returning ≤5 bytes
- `String.prototype.replace` short replacements
- `__torajs_anyv_to_str` returning short results (Bool → `"true"` /
  `"false"`, Null → `"null"`, small Int32 → 1–5 byte decimal)

**Not a win** — string literals already bypass alloc:

- `ssa_lower::intern_string_literal` lowers every literal to
  `Inst::StaticStrRef` pointing at a `.rodata` global. The block carries
  `FLAG_STATIC_LITERAL` in its heap header so `rc_inc` / `rc_dec` /
  `str_free` short-circuit. **No runtime alloc per literal.** SSO would
  not save any alloc here. (8c/8d still bind ShortStr in IR for callsites
  that compose literals at runtime — concat of two short literals, etc.)

The 8a "callsite audit" task confirmed `__torajs_str_alloc_pooled` /
`__torajs_str_alloc` callers are all runtime-computed Strs:
substr_methods.rs (4 sites), symbol.rs (2), json_parse/parse_string.rs (4
sites, currently only empty Str), coerce.rs (1 — `"[object]"` placeholder
which is 8 bytes, NOT eligible for 5-byte SSO), anyvalue/inspect.rs (1).
The IR-side `__torajs_str_alloc` LLVM extern (declared in ssa_inkwell.rs)
serves the same runtime path; literal emit goes through `StaticStrRef`
not through this.

## Bit-space audit — what's actually unused

The Step 7 nanbox layout (`crates/torajs-anyvalue/src/nanbox.rs:54-83`)
divides u64 by top-16-bit value:

| `top16`           | Encoding                                | Notes |
|-------------------|-----------------------------------------|-------|
| `0xFFFE`          | i32 (low 32 bit payload, sign-extended) | `TAG_TYPE_NUMBER` |
| `[0x0007, 0xFFFE)`| f64 (real bits + DOUBLE_ENCODE_OFFSET)  | covers all real f64 |
| `0x0000`          | cell pointer / sentinels / reserved 0    | aarch64 48-bit user-VA |
| `[0x0001, 0x0006]`| **unused**                              | **SSO claim region** |

`top16 == 0x0000` sub-cases:
- `v == 0` — reserved (no encoding uses)
- `v == 0x02` — `VALUE_NULL`
- `v == 0x06` — `VALUE_FALSE`
- `v == 0x07` — `VALUE_TRUE`
- `v == 0x0A` — `VALUE_UNDEFINED`
- `v ∈ [0x0001, 0x0000_FFFF_FFFF_FFFF]` with `(v & 0x02) == 0` — cell ptr

### Why only `top16 == 0x0001` is truly safe

`is_double(v) := (v & TAG_TYPE_NUMBER) != 0 && !is_int32(v)`.
`TAG_TYPE_NUMBER = 0xFFFE_0000_0000_0000` (binary `1111_1111_1111_1110`).

AND-ing `top16` against `0xFFFE`:

| `top16` | `& 0xFFFE` | `is_double(v)` |
|---------|-----------|----------------|
| `0x0001` | `0x0000`  | **false** ✓ |
| `0x0002` | `0x0002`  | **true** ❌ — collides with f64 |
| `0x0003` | `0x0002`  | true ❌ |
| `0x0004` | `0x0004`  | true ❌ |
| `0x0005` | `0x0004`  | true ❌ |
| `0x0006` | `0x0006`  | true ❌ |

**So the multi-marker scheme `top16 ∈ [0x0001, 0x0006]` does NOT work**
without changing `is_double` — every marker other than `0x0001` falls into
the f64 region of the bit pattern. The single-marker choice is forced.

We could relax `is_double` to also check the bottom 48 bits aren't a real
f64 bit pattern, but that's a per-call cost on the f64 hot path —
violates **高性能**. Single marker it is.

### Why `is_cell` needs a tightening

The current `is_cell` (nanbox.rs:111):

```rust
pub const fn is_cell(v: AnyValue) -> bool {
    (v & TAG_TYPE_NUMBER) == 0 && (v & TAG_BIT_TYPE_OTHER) == 0 && v != 0
}
```

`v & TAG_TYPE_NUMBER == 0` only checks `top16 & 0xFFFE == 0` — that lets
`top16 == 0x0001` through (since `0x0001 & 0xFFFE == 0`). Combined with a
ShortStr payload that happens to clear bit 1 (e.g. `"a"` = byte `0x61`,
no bit-1 set, full v = `0x0001_0100_0000_0061`), `is_cell` returns
**true** — misclassifying ShortStr as a heap pointer.

**Required fix:** tighten to strict `top16 == 0` check:

```rust
pub const fn is_cell(v: AnyValue) -> bool {
    (v & TOP_16_MASK) == 0 && (v & TAG_BIT_TYPE_OTHER) == 0 && v != 0
}
```

`TOP_16_MASK = 0xFFFF_0000_0000_0000` already exists. This is a strict
predicate: `top16 == 0x0001` now correctly returns `is_cell = false`.

Audit of `is_cell` callsites (8b will sweep these — currently no
behavioral change since no ShortStr values exist yet):

- `nanbox_ffi.rs:121` `__torajs_anyv_to_number` cell branch
- `nanbox_ffi.rs:152` `__torajs_anyv_to_str` cell branch
- `nanbox_ffi.rs:181-194` `__torajs_anyv_to_bool` cell branch (reads
  Str header)
- `nanbox_ffi.rs:239-251` `__torajs_anyv_strict_eq` cell pair
- `nanbox_ffi.rs:59-65` `__torajs_anyv_rc_inc` / `:81-91` `_rc_dec`
- `nanbox_ffi.rs:318-334` `decode_to_tag_value` (compare / arith / add)

All callsites pre-ShortStr behave identically — the tightening is a
**no-op refactor** when no ShortStr values exist. Once 8b lands the
ShortStr arm, every callsite handles ShortStr **before** falling through
to `is_cell` — order matters.

## Layout — ShortStr encoding

```text
ShortStr AnyValue layout (64-bit):

  bits 63..48: top16 = 0x0001                       (marker, 16 bit)
  bits 47..40: len   = 0..5 (or 0..7 if 3-bit)      (8 bit, or 3 bit)
  bits 39..0 : bytes = 5 × 8 bit, little-endian      (40 bit payload)

Encoded value pattern:
  0x0001 LL XX_XX_XX_XX_XX
         ^^ ^^^^^^^^^^^^^^^
         len  bytes (LE, byte 0 in low byte)

Example: "abc" → len=3, bytes=[0x61, 0x62, 0x63]
  v = 0x0001_03_00_63_62_61
    = (0x0001 << 48) | (3 << 40) | (0x63 << 16) | (0x62 << 8) | 0x61
    = 0x0001_0300_0063_6261
```

**Capacity = 5 bytes** (40-bit payload). Covers:

- All single ASCII characters (1 byte)
- `"true"` / `"null"` / `"NaN"` (3–4 bytes)
- `"false"` (5 bytes — exact fit)
- 1–5 digit decimal Number.toString (`"0"` to `"99999"`)
- JSON delimiters / single-char keys
- 1–5 byte ASCII substrings from `slice` / `substring` / `charAt`

Does **not** cover:

- `"undefined"` (9 bytes) — stays Heap+Str
- `"[object Object]"` (15 bytes) — stays Heap+Str
- Any string ≥ 6 bytes
- Any multibyte UTF-8 string where the encoded length ≥ 6 (e.g. one
  emoji = 4 bytes — fits; but `"日本"` = 6 bytes UTF-8 — does NOT fit)

### Encoding / decoding primitives

```rust
// nanbox.rs additions (Step 8b)

pub const SHORT_STR_TAG: u64 = 0x0001_0000_0000_0000;
pub const SHORT_STR_CAP: usize = 5;

#[inline]
pub const fn is_short_str(v: AnyValue) -> bool {
    (v & TOP_16_MASK) == SHORT_STR_TAG
}

#[inline]
pub const fn short_str_len(v: AnyValue) -> u8 {
    ((v >> 40) & 0xFF) as u8
}

/// Caller asserts [`is_short_str`].
#[inline]
pub fn short_str_bytes(v: AnyValue) -> [u8; SHORT_STR_CAP] {
    let payload = v & 0x0000_00FF_FFFF_FFFF;
    let mut out = [0u8; 5];
    out[0] = (payload      ) as u8;
    out[1] = (payload >>  8) as u8;
    out[2] = (payload >> 16) as u8;
    out[3] = (payload >> 24) as u8;
    out[4] = (payload >> 32) as u8;
    out
}

/// Returns `None` if `bytes.len() > SHORT_STR_CAP`.
#[inline]
pub fn try_box_short_str(bytes: &[u8]) -> Option<AnyValue> {
    if bytes.len() > SHORT_STR_CAP {
        return None;
    }
    let mut payload: u64 = 0;
    for (i, &b) in bytes.iter().enumerate() {
        payload |= (b as u64) << (i * 8);
    }
    Some(SHORT_STR_TAG | ((bytes.len() as u64) << 40) | payload)
}
```

`is_short_str` is **1 cmp + 1 mask** — same cost class as `is_int32` /
`is_cell`. `try_box_short_str` is **branch + 5×OR** in the worst case;
inlined into the IR sites it becomes a constant-folded sequence when
`bytes.len()` is known at compile time (literal case).

## ABI impact — `__torajs_anyv_*` shims need ShortStr arms

The Step-7 immediate-ABI shims (`nanbox_ffi.rs`) all need a new arm
**before** the `is_cell` check. Order of predicates becomes:

```text
is_int32(v)      → primitive path
is_double(v)     → primitive path
is_short_str(v)  → ShortStr path  (NEW — Step 8)
is_null/_undef   → sentinel path
is_bool          → primitive path
is_cell(v)       → heap path
```

Per-shim changes:

| Shim | ShortStr behavior |
|------|-------------------|
| `__torajs_anyv_rc_inc` | **no-op** (no rc — primitive immediate) |
| `__torajs_anyv_rc_dec` | **no-op** |
| `__torajs_anyv_to_number` | Parse 5-byte payload via `__torajs_str_to_number` adapter (8b ports a `parse_short` fn that reads inline) |
| `__torajs_anyv_to_str` | **identity** — return `v` (already a string-shaped AnyValue) |
| `__torajs_anyv_to_bool` | `len > 0` direct (no Str header read) |
| `__torajs_anyv_strict_eq` | ShortStr === ShortStr: u64 ==. ShortStr === Heap+Str: materialize + byte-compare (or short-path inline byte compare). |
| `__torajs_anyv_compare` | ShortStr operand: decode → existing Str compare path |
| `__torajs_anyv_arith` / `_add` | `+` with ShortStr: materialize on demand for concat path (8b adds a `materialize_short_str` helper that allocs Heap+Str only when both operands need to fit a Heap shape) |

The shape "ShortStr → Heap+Str materialize" needs a single helper:

```rust
// 8b additions in nanbox_ffi.rs or coerce.rs
fn materialize_short_str(v: AnyValue) -> *mut u8 {
    debug_assert!(is_short_str(v));
    let len = short_str_len(v) as u64;
    let bytes = short_str_bytes(v);
    let mut block = StrBlock::alloc(len);
    if len > 0 {
        // SAFETY: just alloc'd; sole owner; len ≤ 5 ≤ STR_POOL_PAYLOAD
        unsafe { block.as_bytes_mut(len).copy_from_slice(&bytes[..len as usize]); }
    }
    block.into_raw()
}
```

This is the **dual-mode helper** Step 8b focuses on: every coerce /
compare / concat path that needs a heap Str on at least one side calls
`materialize_short_str` to widen ShortStr to Heap+Str. Reverse direction
(Heap+Str → ShortStr) is **only** done at the producer site if the Str
is ≤ 5 bytes at construction time (`__torajs_str_alloc(src, len)` short-
path in 8c/8d).

## Risks

1. **UTF-8 split inside ShortStr capacity boundary.** If a 5-byte
   ShortStr contains the first 5 bytes of a 6-byte UTF-8 character, the
   ShortStr would carry an invalid UTF-8 sequence. **Mitigation:** SSO
   producer paths (`_short` extern) treat the slice as
   **bytes-only** — same as `__torajs_str_alloc` already does (which
   doesn't validate UTF-8). Downstream operations (`.length`,
   `.charCodeAt`, slice) already work on byte-level Str layout, so
   ShortStr inherits this. **Caveat:** `String.prototype.length` in
   bun returns code-unit count, not byte count — our existing Str
   already implements length as byte-count (a pre-existing semantic
   gap, not introduced by SSO). Filed as Risk #1 in Step 7 close-out
   (see [`v0.7-Phase3-nanbox.md`](v0.7-Phase3-nanbox.md) Risk section).

2. **NaN aliasing — Float64Array bit-fiddle could produce a
   `top16 == 0x0001` value.** A user program that writes raw bits to
   a typed-array could store a value that decodes as ShortStr when
   read as AnyValue. **Mitigation:** typed-array Float64Array read
   path **must** canonicalize NaN bits before storing into an Any
   slot (one bitwise op). Current code already has a deferred
   canonicalization note (Step 7 close-out half-open topic
   "Float64Array NaN canonicalization"); 8b ships the canonicalization
   as part of this work. Cost: one branch per typed-array → Any
   conversion (off the hot path of typed-array element access).

3. **ABI compat for non-Step-7 callers.** Heap+Str pointers passed
   through external C helpers (`runtime_*.c` files that have not been
   ported to Rust yet) treat the input as `uint8_t *` heap. ShortStr
   AnyValue would mis-interpret as a low-address invalid pointer.
   **Mitigation:** every cross-language boundary is an
   `__torajs_anyv_*` shim that already decodes AnyValue immediately;
   no C helper sees a raw AnyValue carrying ShortStr — they receive
   the materialized Heap+Str pointer via `materialize_short_str`. The
   shims themselves enforce this contract.

4. **`is_cell` tightening as silent breaker — full workspace audit
   (corrected 2026-05-27 post 8a-1 grep).** Any callsite outside
   `nanbox_ffi.rs` that uses a cell-imm predicate *before* checking
   `is_short_str` would silently mis-route ShortStr → heap path.
   The earlier 8a draft claimed "no external callers" — that was
   **incomplete**. Full grep `is_cell\|nan_box_is_cell_like\|is_cell_imm`
   finds **9 callsites across 5 crates**, including **5 sister
   predicate definitions duplicating the same weak check**:

   | Crate / file | LOC | Predicate name | Notes |
   |--------------|-----|----------------|-------|
   | `torajs-anyvalue/src/nanbox.rs` | 111 (def) + tests | `is_cell` | canonical — tighten here first |
   | `torajs-anyvalue/src/nanbox_ffi.rs` | 59, 82, 121, 152, 181, 239 (×2), 329 | `is_cell` | 8 shim arms (already covered) |
   | `torajs-anyvalue/src/nanbox_encode.rs` | 148, 174 | `is_cell` | encode-side dispatch |
   | `torajs-anyvalue/src/inspect.rs` | 89, 147 | `is_cell` | debug inspect path |
   | `torajs-anyvalue/src/lib.rs` | 648 | `is_cell` | AnyView constructor |
   | `torajs-rc/src/lib.rs` | 467/474, 494 (def), 514 | `nan_box_is_cell_like` | **duplicate def** — same weak predicate, avoids cross-crate dep on torajs-anyvalue |
   | `torajs-value-drop/src/lib.rs` | 94, 136 (def) | `nan_box_is_cell_like` | **duplicate def** |
   | `torajs-meta/src/reflect.rs` | 63 (def), 110, 150 | `is_cell_imm` | **duplicate def** |
   | `torajs-meta/src/classmeta.rs` | 41 (def), 93, 114 | `is_cell_imm` | **duplicate def** |

   **Each duplicate uses the same weak check**
   `(v & TAG_TYPE_NUMBER) == 0 && (v & TAG_BIT_TYPE_OTHER) == 0 && v != 0`
   — so the ShortStr misclassification bug recurs identically in
   every one of the 5 sister-predicate sites. The tighten **must
   be replicated** to `nan_box_is_cell_like` (×2 def) and
   `is_cell_imm` (×2 def) when 8b lands ShortStr, or 5 crates will
   silently mis-route ShortStr → heap path.

   **Mitigation in 8b:** sweep all 9 callsites in one commit; the
   tighten is a no-op refactor when no ShortStr exists. Consider
   re-exporting `is_cell` from `torajs-anyvalue` (now that the
   workspace pillar is "single source of truth") and deleting the
   4 duplicate definitions — but that crosses crate-dep boundaries
   (`torajs-rc` is below `torajs-anyvalue` in the layer stack; not
   trivially fixable). Documented as Step 8e (close-out) follow-up
   if scope warrants, or deferred to a separate consolidation pass.

5. **5-byte capacity perceived as small.** The choice is bit-budget-
   forced: 64-bit AnyValue minus 16-bit marker minus 8-bit len leaves
   40 bits. A 3-bit-len scheme would free 5 bits but cap len at 7
   (still 5 bytes since payload only fits 5). A 4-bit-len gains
   nothing (44 bit / 8 = 5.5 bytes — can't carry the half byte).
   Tightening payload bytes to 6 (48-bit) would require dropping the
   len field and using a different scheme (e.g. zero-padded fixed-6,
   inline NUL terminator, or top16-encoded length) — each adds
   per-call decode cost or violates **正统** by departing from the
   single-marker JSC-aligned shape. **5 bytes is the disciplined
   maximum.**

## Decision points — takagi sign-off

The 8a doc commits to the **single-marker `top16 == 0x0001`** scheme
(forced by `is_double` bit-pattern; see "Why only top16 == 0x0001 is
truly safe"). The remaining open questions:

### (a) bytes-only vs char-aware boundary

**Recommended: bytes-only.** Match `__torajs_str_alloc` existing
behavior. Avoids per-call UTF-8 char-boundary parsing (which would
violate **高性能**). Edge case: a 5-byte ShortStr split mid-UTF-8 carries
invalid bytes — same edge case exists today for any byte-level Str op
(`slice(0, 2)` on `"日本"` already returns invalid 2 bytes); we are
not introducing a new bug class, just inheriting the existing one.

Alternative: char-aware boundary. Per-call UTF-8 decode to find the
last complete-char position ≤ 5 bytes. Adds branch + iter per call.
Rejected.

### (b) 5-byte capacity (3-bit vs 8-bit len encoding)

**Recommended: 8-bit len.** Wastes 3 bits but simplifies the decode
path (single byte read) + leaves room for future 7-byte capacity if we
ever change the marker scheme.

Alternative: 3-bit len (0..7, only 0..5 valid). Frees 5 bits for a
"sentinel" or future bit-tagged variant. Microscopic gain; not worth
the divergence.

### (c) ShortStr through `rc_inc` / `rc_dec`

**Recommended: no-op** (same as how `rc_inc(int32_value)` is no-op
today). ShortStr is a primitive immediate — no heap, no refcount. A
caller invoking `__torajs_anyv_rc_inc(short_str_value)` correctly
identifies it as primitive via `is_short_str` and returns.

Alternative: panic in debug builds. Adds noise; the primitive case is
the documented behavior of every NaN-box primitive shim. Rejected.

## What 8a is NOT

- 8a does **not** define the IR encode sequence (8d's job).
- 8a does **not** define the collections::Map hash short-path (8d
  optional polish).
- 8a does **not** modify any code — pure design.
- 8a does **not** decide whether to canonicalize Float64Array NaN
  bits in the same commit (Step 7 close-out topic; 8b will absorb).
- 8a does **not** rule out a future 7-byte ShortStr variant via
  redesign of the marker scheme — but any such redesign would be a
  separate substrate revision (`docs/v0.7-Phase3-Step8b-sso-v2.md`)
  with full bit-audit + ABI sweep, not an in-flight edit.
