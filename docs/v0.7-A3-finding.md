## Design — new `torajs-io` crate

### Crate scaffold

```
crates/torajs-io/
├── Cargo.toml
├── src/
│   ├── lib.rs          — pub use stdout::*; pub use stderr::*; ...
│   ├── stdout.rs       — buffered writer + flush + extern entry points
│   ├── stderr.rs       — same shape; A3 scope = stdout only, stub stub
│   └── buf.rs          — TLS line-buffer impl shared by stdout/stderr
```

### Public extern entry points (replace `putchar` in Rust callers)

```rust
// crates/torajs-io/src/stdout.rs
//
// Per-byte buffered write to stdout. Mirrors libc `putchar`
// semantics: returns the byte written (cast to i32), or -1 on
// short-write (caller never observes — buffered).
//
// SHARED buffer state: a TLS line-buffer. Flushes on newline
// (`\n`) or on `__torajs_io_flush` call (process exit hook + at
// any explicit `console.log` write boundary). Cross-call ordering
// is preserved without cross-thread contention.
//
// Replaces every `extern "C" putchar` extern + every call site
// across torajs-str, torajs-arr, torajs-anyvalue, torajs-num.
#[unsafe(no_mangle)]
pub extern "C" fn __torajs_io_putc_stdout(c: i32) -> i32 {
    buf::push(c as u8, /* fd */ 1);
    c
}

#[unsafe(no_mangle)]
pub extern "C" fn __torajs_io_write_stdout(buf_p: *const u8, len: u64) {
    let s = unsafe { core::slice::from_raw_parts(buf_p, len as usize) };
    buf::write(s, /* fd */ 1);
}

#[unsafe(no_mangle)]
pub extern "C" fn __torajs_io_flush() {
    buf::flush_all();
}
```

`buf` module wraps a TLS `Vec<u8>` (or fixed `[u8; 4096]` line-
buffer) + `torajs_syscall::write(fd, &buf)` for the actual fd
write. On newline byte, flushes. Mirrors stdio buffering.

### IR-emitted callers (Hard bucket)

The 3 IR-emitted printers (`define_print_bool` / `_print_i64` /
`_print_f64`) currently emit per-byte putchar calls inline in
their generated LLVM IR. The cutover:

1. Replace the `m.add_function("putchar", ...)` extern declare
   with `m.add_function("__torajs_io_putc_stdout", ...)`. Same
   signature.
2. Inline call sites in `define_print_*` switch from `putchar` to
   `__torajs_io_putc_stdout`. **No call-site shape change — only
   the symbol name changes.**
3. At process exit (or right before exit() / before reading
   stdout's expected content in conformance test), emit a single
   `call void @__torajs_io_flush()`. Already-buffered bytes hit
   stdout in order.

Alternative considered: emit `call __torajs_io_write_stdout(buf,
len)` directly with a stack buffer pre-filled with the digit string
(for `print_i64`). Higher win (1 write per int instead of N
putchar calls) but bigger IR refactor — deferred to Step 14-d (a
follow-on optimization).

## Why this is "正统"

- **Mirrors libc stdio buffering** without depending on libc — a
  TLS line-buffer + `write(2)` is the textbook implementation of
  `putchar` + `printf`'s buffered stdout (FILE* internals). Every
  POSIX libc does exactly this; we're replacing the layer with
  our own write while keeping the same external semantics.
- **Single extern boundary** — all Rust + IR callers go through
  one extern entry point (`__torajs_io_putc_stdout`). No
  per-crate divergence.
- **No silent-wrong** — the cutover is mechanical (extern name
  change + call site name change). Byte-equal output is
  trivially provable; bun-parity fixtures catch any drift.

## ROI estimate

- Removes the only libc dep on the hot stdout path. After 14-c,
  `__torajs_libc_malloc` family is the remaining libc surface
  in user binaries (handled by A5 audit).
- Perf-neutral on most fixtures (per-byte putchar latency ≈
  per-byte buffered-write latency at the TLS-buf push call). On
  print-heavy fixtures (`console-log-Nk`), 14-d's single-write
  refactor may yield 10-30% speedup on the print loop. Not on
  any current A3 gate.
- Binary size: per-fixture −1 dynamic-link entry (libc.dylib's
  `_putchar` symbol). `/tmp/<bench-bin>` artifact reduces by
  ~50-100 B per program (varies with the dyld stub overhead).
